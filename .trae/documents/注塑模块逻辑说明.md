# 注塑模块 (InjectionModule) 业务逻辑说明书

## 1. 概述
注塑模块主要用于实时监控注塑产线的生产状态、产量统计及质量分析。系统通过后端 API 实时查询数据库中的生产记录，并在前端进行指标计算与可视化展示。

---

## 2. 数据源 (后端逻辑)

### 2.1 API 接口
- **接口地址**: `/api/injection`
- **请求方式**: `GET`
- **更新频率**: 前端每 3 秒轮询一次
- **文件位置**: `server/index.js`

### 2.2 数据库查询逻辑
系统直接查询 `auto_line_table` 表，获取**当天 00:00:00 之后**的所有生产记录。

```sql
SELECT 
    CreatedTime,   -- 创建时间 (用于计算时长、按小时分组)
    GroupId,       -- 批次号
    PartNumber,    -- 产品条码
    IsOk,          -- 合格状态 (1=OK, 0=NG)
    IsPrinted      -- 打印状态
FROM auto_line_table
WHERE CreatedTime >= CAST(GETDATE() AS DATE)  -- 仅查询当天数据
ORDER BY CreatedTime ASC                      -- 按时间正序排列
```

## 3. 指标计算逻辑 (前端逻辑)

前端接收到当天的所有记录后，在浏览器端实时计算以下核心指标。

### 3.1 核心指标 (Metrics)

| 指标名称 | 计算公式/逻辑 | 说明 |
| :--- | :--- | :--- |
| **生产数量 (Total Count)** | `data.length` | 当天记录的总行数。 |
| **合格数量 (OK Count)** | `data.filter(d => d.IsOk).length` | `IsOk` 为 `true` (或 1) 的记录数。 |
| **不合格数量 (NG Count)** | `Total Count - OK Count` | 生产总数减去合格数。 |
| **运行时长 (Run Time)** | `Current Time - First Record Time` | 从当天**第一条记录的时间**开始，到**当前系统时间**的时间差。<br>格式化为 `HH:MM:SS`。<br>*注：如果当天无数据，时长显示为 00:00:00。* |

### 3.2 生产速度 (Speed) 计算问题分析与优化方案

**当前存在的问题：**
目前的计算逻辑是 `Total Count / Run Time (Hours)`。
如果程序启动较晚（例如 10:00 启动），而数据库中 08:00 就有第一条记录：
- `Run Time` 会从 08:00 开始算起（例如 2 小时）。
- `Total Count` 包含了这两小时的所有产量。
- 此时计算出的平均速度是正确的（例如 200 件 / 2 小时 = 100 PPH）。

**但如果出现以下情况，数据会严重失真：**
假设程序是 10:00 启动，但数据库里**只有** 09:59 的一条数据（可能是刚刚开机生产，或者数据采集才开始）。
- `Run Time` = 10:00 - 09:59 = 1 分钟。
- `Total Count` = 1 件。
- `Speed` = 1 / (1/60) = **60 PPH**。
- **但如果此时突然涌入之前积压的 100 条数据**（时间戳都是 10:00），或者仅仅过了 1 分钟又生产了 10 个：
- `Run Time` = 2 分钟。
- `Total Count` = 11 件。
- `Speed` = 11 / (2/60) = **330 PPH**。

这种基于“全天累计平均”的算法，在**刚开始运行**或者**数据断断续续**时，确实会造成速度波动巨大，且不能反映**当前的瞬时速度**。

**建议优化方案 (Rolling Average)：**
不再计算“全天平均速度”，而是计算**最近 N 分钟的实时速度**。

**新逻辑提案：**
1.  **取最近窗口**：只取最近 10 分钟（或 30 分钟、1 小时）内的生产记录。
2.  **计算产量**：统计这 10 分钟内的 `Count`。
3.  **计算时间**：固定为 10/60 小时。
4.  **公式**：`Speed = (最近10分钟产量) * 6`。

**优点**：
- 能反映当前的生产节拍。
- 不受早上开机时间早晚的影响。
- 即使中间停机 2 小时，也不会因为分母过大导致当前速度被拉得很低。

### 3.3 图表分析 (Charts)

系统将当天数据按**小时**进行分组统计，生成双轴图表：

- **X轴 (时间轴)**:
  - 动态生成小时刻度 (如 `08:00`, `09:00`, `10:00`...)。
  - 根据实际数据产生的时间段自动延伸。

- **Y轴 (左轴 - 产量)**:
  - **逻辑**: 统计该小时段内的记录总数。
  - **最大值**: 动态计算，确保柱状图不会顶格 (Max + 50)。

- **Y轴 (右轴 - OEE/良率)**:
  - **逻辑**: `(该小时合格数 / 该小时总数) * 100%`。
  - **范围**: 0 - 100%。

---

## 4. 异常处理
- **无数据状态**: 如果数据库中没有当天的记录，所有指标显示为 0 或 00:00:00，图表显示为空。
- **数据延迟**: 由于采用 3 秒轮询机制，界面显示的数据最大可能有 3 秒的延迟。
